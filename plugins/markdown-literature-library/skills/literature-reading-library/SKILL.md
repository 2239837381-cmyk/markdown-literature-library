# 离线文献阅读库

将已核验 Markdown 生成单文件 HTML。若需要严谨研究关系，先使用 `literature-knowledge-map`；没有索引时只能展示基于可见关键词的初步分类。

## 执行

```text
python ../../scripts/build_library.py <Markdown目录> <输出.html>
```

生成器同时写入增量清单，使用相对路径构造稳定文献 ID。重建 HTML 时，未改名文献的浏览器批注仍可关联；报告新增、更新、未变和移除的文件。

## 体验与数据

- 首屏直接呈现研究关系和书架。题名融入低饱和复古书脊，可缩略但清晰可读。
- 点击书籍有抽取、摊开动效；减少动态效果设置下仍可使用。
- 阅读页右侧显示批注。选中正文后右键选择四色高亮，批注可编辑、定位、删除和清空。
- 支持按当前文献及颜色筛选导出 Markdown，也支持导出全部文献批注。
- Markdown 必须安全转义；文献内容不能成为可执行 HTML 或脚本。

## 分类、图谱与书架可读性

- 主题分类必须依据 Markdown 中明确写出的研究问题、研究对象、案例、机制和结论；题名或单个关键词只能作为线索，不能单独决定类别。
- 城市空间、更新、领域变化、生态修复等研究，应与社区治理、共同体、社会组织等研究区分。文献若跨主题，可显示多个标签；主主题必须反映其主要研究对象。
- 研究图应呈现文献库中实际存在的并行研究线索。没有全文证据时，不要把多个主题强行画成线性发展阶段，也不要把“共同体”作为笼统容器。
- 每个主题节点须显示可解释的主题名、简短的对象或机制说明及文献数量；点击后只展示该主题文献。
- 书架默认分页展示，建议每页 8—12 篇；切换主题或搜索条件时重置页码。不得将全部文献挤在窄书脊上。
- 书名必须位于可见层，不能被书脊边框、伪元素或背景遮挡。书名过长时允许多行截断，并保留完整题名的悬停提示或打开后的扉页。

## Markdown 表格

- 连续的 Markdown 表格行必须整体渲染为同一张 `<table>`，不能按行各自包裹成多个表格。
- 识别 `|---|---|` 一类表头分隔行，分别输出 `<thead>` 与 `<tbody>`；单元格数量不齐时以表头列数为准补齐或留空，避免列错位。
- 为表格提供 `border-collapse`、统一单元格边框和窄屏横向滚动容器；不要把表格行再包进普通段落。

## 验证

核对文献数量、增量清单、稳定 ID、JavaScript 编译、研究图、书架、分页、书名可见性、阅读抽屉、Markdown 表格、右键菜单、批注持久化和导出按钮。对至少一篇含表格的 Markdown 进行渲染检查。批注只保存在当前浏览器中，清除站点数据会删除它们。
